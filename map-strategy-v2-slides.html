Core Concept

The FIFO Principle

Our slide carrier works like a queue — first tile in, first tile out.
This one property locks the entire strategy together.

Why this works
  • Collect tiles in exact same order as the scanned mosaic pattern

Step 1

Navigate to Mosaic Frame

go_to_mosaic() sequence
set_gyro_zero() # zero at start turn_pivot(50) # angle away from tiles go_until_black() # find first nav line turn_pivot(90) set_gyro_zero() # RE-ZERO here # 0° = facing mosaic turn_yaw(15) # small correction go_until_black() turn_pivot(0) go_until_black() # arrive cell [0]
⚠ Why 50°?
  • Source D (yellow tiles) sits nearest to the start area
  • A straight exit would crash into the tile stacks
  • 50° angles the robot diagonally into open field
  • First black line hit = safe entry to the nav lane
⚡ Why re-zero the gyro?
  • Initial 50° turn leaves gyro in an awkward offset
  • Re-zero gives clean absolute reference for the whole run
  • 0° = facing mosaic / into sources
  • 90° = right / south (toward start)
  • −90° = left / north (away from start)
  • 180° = back toward the main nav line
✓ End state
  • Robot at mosaic cell [0] (top-left of frame)
  • Heading locked at 0°
  • Ready to begin serpentine scan

Step 3 — collect_all_blocks()

List → Pickup Order

The collection loop
for index in range(12): next_color = mosaic_list[index] # e.g. "A", "C", "B", "A" ... if current_location == "mosaic": go_mosaic_to_source(next_color) elif current_location == next_color: second_block() # STAY — no travel else: go_source_to_source( current_location, next_color ) current_location = next_color # update
Example: mosaic_list = ["A","A","C","B"]
index 0: → Source A (from mosaic)
index 1: STAY at A (same source! second_block)
index 2: → Source C (travel from A)
index 3: → Source B (travel from C)
⚡ second_block() saves time
  • Two consecutive tiles need same color
  • Robot does NOT leave the source
  • Just turns slightly, grabs the next tile
  • Saves ~3–5 seconds per duplicate pair

Navigation Core

Black Line Detection

go_until_black() — the fundamental nav primitive
def go_until_black(): robot.drive(SLOW_SPEED, 0) while not is_black(): wait(10) stop_robot() def is_black(): return color_sensor_A.reflection() < 35
go_until_nth_black(n) — count intersections
def go_until_nth_black(target_count): count = 0 while count < target_count: go_until_black() count += 1 if count < target_count: drive_mm(60) # nudge past line # avoid re-detecting!
How the source lane works
  • Source lane = a vertical black line on the mat
  • Each source has a horizontal branch intersecting it
  • Robot counts intersections to know how far to travel
  • 1 intersection = Source B or C (nearest to mosaic)
  • 2 intersections = Source A or D (furthest from mosaic)
⚠ The 60mm nudge trick
  • After hitting a black line, sensor is still ON that line
  • Next go_until_black() would re-detect the same line instantly
  • Nudge 60mm forward to physically clear the line
  • Only nudge between counts, not after the final one
return_to_main_line()
turn_pivot(180) # face source lane go_until_black() # drive back to it

Steps 4 & 5

Return & Place

place_tiles_serpentine() — mirrors scan movement
for i in range(12): release_one_tile() if i < 11: move_to_next_mosaic_slot(i) # Row 1 [0→3]: drive forward per cell # End row 1 [3]: turn 90, drive ROW_H, turn 180 # Row 2 [4→7]: drive forward (heading 180) # End row 2 [7]: turn 90, drive ROW_H, turn 0 # Row 3 [8→11]: drive forward per cell
Why no color decisions here?
  • FIFO slide already holds tiles in the correct order
  • Robot just releases one tile at each cell position
  • No color sensor reading during placement
  • No branching logic — pure mechanical execution
  • Placement movement mirrors scan movement exactly
