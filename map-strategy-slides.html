Mission Overview

The Challenge

THE PROBLEM

A 3×4 mosaic frame sits in the center of the field. The color pattern inside is randomized each round using a paper sheet placed under the frame.

THE GOAL

Read the pattern, then place the correct colored tiles into each of the 12 frame slots. Max 120 points (10 per correct tile).

TILE COLORS (Fixed Sources)

YELLOW ×6 BLUE ×6 GREEN ×6 WHITE ×6

KEY CONSTRAINT

Source tile positions are fixed — not randomized. Only the frame pattern changes. This is the key to our strategy.

Step 1 · Scanning

Slider Scanner Mechanism

The color sensor is mounted facing downward on a linear slider. The slider extends over the mosaic frame, scans row by row, then retracts.

SCAN PATTERN (Serpentine)

Row 1 → Left to Right

Row 2 → Right to Left

Row 3 → Left to Right

WHY SERPENTINE?

Scan order = placement order. No coordinate translation needed. The list index directly maps to frame slot position.

Step 2 · Logic

Core Algorithm

01
Scan & Store
Extend slider over mosaic frame. Color sensor reads each of 12 positions in serpentine order. Append each result to mosaic_order[].
02
Pre-compute Pickup List
Since source tile positions are fixed, generate pickup_order[] from mosaic_order[]. This tells the robot which color to grab next.
03
Navigate → Pick → Place Loop
For each tile in pickup_order[]: call go_to_color(current_pos, target_color) → grab tile → return to frame → place at next slot.
04
Update Position Tracker
After each pickup, update current_pos to the color just grabbed. This drives the correct route function for the next navigation call.
Step 3 · Navigation

Route Function Matrix

Since source tile positions are fixed, we pre-program all possible point-to-point routes. 4 origins × 4 destinations = 16 route functions. Call them with (from, to).

FROM \ TO 🟡 YELLOW 🔵 BLUE 🟢 GREEN ⬜ WHITE
🏠 MOSAIC Fwd → L1 → R2 Fwd → R1 → Fwd Fwd → L1 → Fwd Fwd → R1 → L2
🟡 YELLOW — Back → Turn → Fwd Back → R1 → Fwd Back → L1 → Fwd
🔵 BLUE Back → Turn → Fwd — Adj → R1 → Fwd Adj → L1 → Fwd
🟢 GREEN Back → L1 → Fwd Adj → Fwd → R1 — Adj → R1 → Fwd
⬜ WHITE Back → R1 → Fwd Adj → Fwd → L1 Adj → L1 → Fwd —

* Fwd=Forward, L1=1st intersection Left, R2=2nd intersection Right, Adj=Adjacent path. Fine-tune per actual map layout.

Verification

Logic Validation

✅
Color Sensor Detection
LEGO Spike Prime color sensor natively distinguishes Yellow, Blue, Green, and White. Downward-facing position is ideal for reading flat tiles through the frame opening.
✅
PyBricks List Storage
Python lists in PyBricks handle all 12 elements easily. mosaic.append(color) works natively. No memory concerns.
✅
Serpentine Scan = Place Order
Scanning in serpentine order creates a 1-to-1 mapping between list index and frame slot. Zero coordinate math needed during placement loop.
✅
Pre-programmed Routes (No Horiz. Scan)
Fixed source positions = no dynamic detection needed. Avoids build complexity of horizontal sensor. Dictionary-based route lookup is clean and fast.
⚠️
Color Names: No RED!
Official WRO 2026 rules define 4 colors as Yellow, Blue, Green, White. There is no red tile. Update your code and route functions accordingly.
⚠️
White vs. Light Sensor Ambient
White tile detection can be affected by ambient light. Calibrate sensor.color() thresholds carefully, especially for white vs. the light-colored frame.
